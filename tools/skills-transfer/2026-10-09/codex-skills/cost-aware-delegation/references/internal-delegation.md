# Внутренний исполнитель: выбор и приёмка

Применять после выбора допустимого внутреннего маршрута. При проблемах внешнего провайдера сначала действует временное правило остановки и обсуждения из SKILL.md, а не автоматический fallback.

- Простая изолированная работа — `gpt-6-luna`; стандартная и сложная реализация — `gpt-6-sol`. Astra ставит задачу, решает неоднозначности и принимает результат. Terra/5.6 — резерв, не обязательная промежуточная ступень. Это предпочтения владельца, не доказательство превосходства или стоимости модели.
- Сверять доступность идентификаторов и параметры с инструментом запуска. Для обычной Luna/Sol начинать с `medium`, если поддерживается; усиливать по сложности, без автоматического максимума. Если модель недоступна, обозначить ограничение, не выдавать другую модель за выбранную.
- Для смены модели использовать независимый короткий контекст (`fork_turns="none"`, если этого требует инструмент). Передавать связный пакет реализации с проверками, а не копию всей истории. Внутренние исполнители расходуют общий лимит Codex, не независимый внешний бюджет.
- Фиксированного лимита в один помощник нет: выбирать число исполнителей по полезной независимой работе, бюджету и лимитам инструментов. Параллельное выполнение допустимо в пределах разрешённого задания. Не создавать отдельный пользовательский чат вместо внутреннего помощника. Завершающие мелкие правки делать локально, когда координация дороже работы.
- Поручение содержит результат и критерии готовности, рабочий каталог, разрешённые файлы, нужные инструкции, запретные области, проверки и короткий отчёт. Общим файлам назначать одного владельца. При необходимости выйти за границы помощник сообщает родителю, а не расширяет scope и не делегирует дальше.
- Пока помощник работает, выполнять независимую полезную часть; не повторять его полную работу и не опрашивать часто. Дождаться результата и принять его перед завершением задачи.
- Проверить соблюдение scope, сохранность пользовательских изменений и достаточность доказательств. Отчёт агента не доказывает личную проверку родителем; зелёные backend-тесты не доказывают UI. Не запускать ещё одного проверяющего автоматически.
- При ошибке дать одну предметную корректировку с наблюдаемыми фактами. При повторной неудаче уточнить причину: Sol для реализации, Astra для неоднозначного решения. Не повторять одинаковые попытки и не повышать модель из-за инфраструктурной ошибки.
- Не обещать проценты экономии без замеров. При сравнении учитывать лимит Codex отдельно от внешних пулов; токены, кэш и время не переводить в проценты подписки без подтверждённого измерения.
