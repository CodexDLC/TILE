# Antigravity CLI: запуск, приёмка, квоты

## Внешний исполнитель: официальный Antigravity CLI

Пользователь разрешил использовать установленный официальный Antigravity CLI как дополнительного исполнителя в пределах текущего задания. Codex ставит ограниченную задачу, запускает CLI, получает ответ и проверяет результат в том же чате. OmniRoute для этого не нужен. Подписки Google и Codex использовать через официальные клиенты; не извлекать и не импортировать их токены в шлюзы.

**Среди исполнителей по подписке сначала Antigravity, внутренние лимиты Codex — в последнюю очередь.** После оценки бесплатного API через OmniRoute выбирать официальный Antigravity CLI, если задача подходит, доступна авторизованная сессия, модель и достаточная квота. Приоритет бесплатного API описан выше; таблица Luna/Sol применяется к внутреннему резерву.

Codex остаётся координатором: формулирует задание, разрешает сложные неоднозначности и принимает результат. Внутренних Luna/Sol использовать как резерв, когда Antigravity недоступен, квота исчерпана, задача требует возможностей текущей среды, которые внешнему исполнителю недоступны, или после одной предметной корректировки результат всё ещё неудовлетворителен. Короткие ответы и мелкие завершающие правки выполнять локально, если запуск CLI обойдётся дороже самой работы. Не запускать внутреннего помощника только по привычке; при выборе резерва кратко назвать причину.

Внутри Antigravity сначала выбирать подходящую экономную модель по таблице ниже, учитывая свежую квоту обоих пулов. Не расходовать Opus или максимальное усилие для простых задач только ради экономии Codex. Число исполнителей выбирать по независимости работы, свежей квоте и возможностям CLI; фиксированного ограничения одним исполнителем нет. Внешнему исполнителю не поручать дальнейшее делегирование без отдельного разрешения. Исчерпание лимита самого Codex может блокировать координацию и проверку разрешений: наличие квоты Antigravity не устраняет этот блокер.

| Задача | Предпочтительная модель Antigravity |
|---|---|
| Поиск по заданным материалам, документация, переводы, простой анализ | Gemini Flash, низкое или среднее усилие |
| Обычная разработка и отладка по ясному заданию | Gemini Pro; Claude Sonnet для задач, где его пригодность оправдывает расход дефицитного пула |
| Сложный анализ, архитектурный вопрос, трудная ошибка | Gemini Pro или Claude Opus; выбирать по задаче и доступной квоте |

Это рабочая маршрутизация, а не гарантия качества или стоимости. Не начинать с Opus или максимального усилия без причины. GPT-OSS использовать только после проверки доступности и пригодности. Получать актуальные идентификаторы через `agy models`, не считать сохранённый список постоянным. 3 октября 2026 были доступны Gemini Flash/Pro и Claude Sonnet/Opus; короткий запрос проверен только на `gemini-3.8-flash-low`.

### Запуск и приёмка

#### Проверенный запуск из Codex на Windows (04.10.2026)

- CLI установлен в `%LOCALAPPDATA%\agy\bin\agy.exe`. В песочнице Codex он может сообщать `Access is denied` для логов/SQLite и `You are not logged into Antigravity`, хотя пользователь уже авторизован. Эти сообщения не доказывают отсутствия авторизации или недоступности CLI.
- Для доступа к существующему профилю запускать через `exec_command` с `sandbox_permissions="require_escalated"` и конкретным `justification`, используя штатное согласование. Не менять ACL, не копировать токены и не применять обход разрешений. `--sandbox` самого Antigravity не заменяет разрешение на запуск из песочницы Codex.
- Сначала выполнить `agy.exe models` вне песочницы. При необходимости проверить ответ коротким headless-запросом из нейтрального каталога: без проектных файлов, с явным запретом чтения файлов, инструментов, правок и делегирования. На 04.10.2026 такой запрос к `gemini-3.8-flash-low` вернул `SUCCESS`; это подтверждает выполнение запроса, но не остаток квоты и не разрешение передавать любые данные проекта.
- Для рабочего поручения указывать реальный `workdir` проекта, разрешённые файлы, запрет доступа к `.env`, ключам, базе и персональным данным, если они не нужны. Передача необходимого исходного кода остаётся в пределах пользовательского разрешения и проверки безопасности конкретного вызова.
- При отказе инструмента сообщить пользователю точную причину и обсудить допустимый способ продолжения. Не объявлять Antigravity недоступным вообще и не переключаться молча на внутренние лимиты Codex. Отказ нельзя обходить; разрешённые диагностические проверки без проектных данных отличаются от отклонённой передачи файлов.

- Windows: бинарник обычно `$env:LOCALAPPDATA\agy\bin\agy.exe`. Проверять существование и `--version`; не переустанавливать автоматически. Авторизацию пользователь проходит сам.
- Проверенный шаблон PowerShell (в рабочем каталоге задания):

```powershell
& "$env:LOCALAPPDATA\agy\bin\agy.exe" --model gemini-3.8-flash-low --mode plan --sandbox --print-timeout 45s --output-format json -p '<ограниченное самодостаточное задание>'
```

- Модель и время подбирать под задачу; 45 секунд — предел короткой проверки, не обязательный предел разработки. `plan` и `--sandbox` не гарантируют полный запрет изменений. Для исследования явно запрещать инструменты или запись, если они не нужны; для разработки задавать разрешённые файлы и проверки, соблюдая разрешения CLI и Codex. Не применять `--dangerously-skip-permissions`.
- Получать `status`, `response`, `usage` и код завершения. JSON со `status=SUCCESS` не заменяет проверку результата, изменений и тестов. Не копировать всю историю чата: передавать только нужный контекст. Даже проверка с коротким ответом использовала около 15 тысяч входных токенов; группировать связную работу, не запускать CLI ради мелких ответов.
- В песочнице Codex авторизованная сессия может быть недоступна. В проверенной среде потребовался запуск через предусмотренный инструментом доступ вне песочницы. Использовать штатную проверку разрешений; при отказе или лимите не обходить её, сообщать фактический блокер.

### Квоты и расходы

- В интерактивном Antigravity CLI `/usage` (или `/quota`) обновляет панель квот, `/credits` показывает кредиты. `/settings` → `Use G1 Credits = off` ограничивает использование дополнительных кредитов после исчерпания основной квоты. Не включать расход дополнительных кредитов без поручения владельца.
- В подтверждённой панели Gemini Flash/Pro делят один пул, Claude Opus/Sonnet/GPT-OSS — другой. У каждого есть недельная и пятичасовая квота. Переключение внутри группы не даёт новый лимит. Остатки и время обновления изменяются; не сохранять показанные проценты как постоянные.
- Эти два пула Antigravity независимы друг от друга и от Codex. По наблюдению владельца пул Claude/GPT существенно более ограничен; не расходовать Sonnet/Opus на обычную рутину, когда подходит Gemini. Для простой рутины выбирать Flash, для разработки — Pro; Claude сохранять для задач, где он даёт нужное качество, или когда подходящий Gemini недоступен. Выбор сверять со свежей панелью, а не с сохранёнными процентами. Низкий остаток одного пула не означает исчерпания второго.
- Перед большой задачей учитывать свежую квоту. Если автоматическое чтение недоступно, получить текущую панель от пользователя; не выдавать токены из `usage` за остаток подписки. Автоматический сбор процентов и остановка по порогу пока не реализованы.
- При исчерпании квоты завершить попытку, сохранить результат и точку остановки. Перейти на другой доступный разрешённый пул или внутреннего исполнителя по смыслу задачи; не повторять запросы в цикле и не покупать кредиты.

Официальные справки: [CLI/headless](https://antigravity.google/docs/cli/headless/), [квоты](https://antigravity.google/docs/cli/commands/usage), [кредиты](https://antigravity.google/docs/cli/credits/). Читать при изменении поведения, без повторного изучения документации перед каждым запуском.
