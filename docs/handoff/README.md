# Передача TALE автору

Обновлено: 2026-10-10. Автор работает с собственным Codex и поручает ему запуск и технические действия обычными словами. Эта запись — состояние подготовки, а не доказательство запуска на новом компьютере.

## Согласовано владельцем

- Работа автора ведётся в `develop`. При этой передаче `main` и `develop` указывают на один коммит; дальнейшая работа автора идёт в `develop`.
- Локально используются SQLite и фотографии на диске, без обязательного Docker.
- Код и временный архив глобальных навыков передаются через публичный [CodexDLC/TILE](https://github.com/CodexDLC/TILE), как явно выбрал владелец 2026-10-10. Готовые резервные архивы — через Syncthing. Живую базу и `.git` между компьютерами не синхронизировать.
- Первую настройку разработчик выполняет вместе с агентом. Автору не требуется самостоятельно выполнять команды.
- Предпочтение для её Codex: Sol — основной исполнитель и приёмка, Luna — простые изолированные поручения. Мелкие действия выполнять без помощника. Настройка моделей относится к её установке Codex и не применяется этим файлом к каждому агенту. Доступность моделей и действующие глобальные правила проверяются на новом компьютере; внутренние помощники используют общий лимит аккаунта.

## Известные ограничения

Установка на новом компьютере и полный авторский сценарий пока не проверены. Старую `.venv`, созданную с editable-пакетами, между компьютерами не переносить; окружение создаётся заново по lock-файлу.

Переменная `UV_CACHE_DIR` на конкретной машине может указывать на старое расположение проекта. При ошибке доступа к такому кэшу инструкция агенту предусматривает доступный кэш в текущем корне проекта; эта проблема не требует изменения зависимостей.

Проектная SQLite-база и media не переключаются вместе с Git-ветками. `git pull` и откат коммита не являются восстановлением материалов.
