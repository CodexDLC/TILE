# Инструкция агенту на компьютере автора

Эти действия выполняет Codex. Автор сообщает желаемый результат обычными словами. Первую настройку разработчик проводит вместе с агентом; она ещё не завершена.

## Перед началом

1. Найти корень открытого проекта по `AGENTS.md` и `pyproject.toml`, не полагаться на путь другого компьютера. Прочитать проектные инструкции и сохранить известный авторский режим.
2. Проверить `git status --short` и `git branch --show-current`. Рабочая ветка — `develop`; локальные изменения сохранять. Ветки разделяют код, но не данные.
3. Проверить наличие `uv`, Python 3.14 и актуального `uv.lock`. Старую `.venv` между компьютерами не переносить.
4. Зависимости устанавливаются из PyPI по lock-файлу, включая обычные пакеты и шесть `codex-*`: ai 0.2.6, core 0.5.0, django 0.7.0, django-cli 0.4.0, platform 0.6.0, services 0.1.4. Локальные исходники `codex_tools` не требуются. Не обновлять lock-файл ради запуска и не подставлять локальные пути.

## Первая настройка с разработчиком

- Получить проект из `https://github.com/CodexDLC/TILE.git` в согласованную новую папку: `git clone --branch develop https://github.com/CodexDLC/TILE.git`. Репозиторий публичный по выбору владельца; рабочие данные и `.env` в нём отсутствуют. Проектные и библиотечные навыки находятся в `.agents/skills/`; временный архив глобальных навыков устанавливать вручную по `tools/skills-transfer/2026-10-09/README.md`, не подключать как активные инструкции целиком.
- Согласовать фактическую папку проекта, версию кода и библиотек, учётную запись автора, исходную базу и фотографии. Установить навыки по ссылкам в README, затем проверить их обнаружение новым разговором.
- Создать новое окружение через `uv sync --locked --extra dev`. При ошибке сохранить причину, не заменять библиотеки случайными версиями. Если ошибка доступа вызвана `UV_CACHE_DIR`, указывающим на старую папку, из фактического корня проекта задать `$env:UV_CACHE_DIR = Join-Path (Get-Location) '.uv-cache'` и повторить ту же установку. Это изменение действует в текущей сессии терминала.
- Подготовить локальные настройки на основе `.env.example`. Значения-заглушки не являются готовыми ключами. Не подключать рабочую удалённую базу разработчика. Если переносится существующая база с зашифрованными полями, согласовать перенос соответствующего ключа отдельно: новый случайный ключ старые данные не расшифрует.
- Проверить выбранный backend и путь к базе без вывода секретов. При стандартных локальных настройках SQLite лежит в `data/db/atlas.sqlite3`, фотографии — в `src/atlas/media/`. `DATABASE_URL`, `IS_DOCKER` и альтернативные env-файлы могут изменить конфигурацию; эти пути не считать универсальными.
- В `core/settings/base.py` могут загружаться корневой `.env`, `src/atlas/.env` и файлы по `ENV_COMMON_PATH`/`ENV_PROJECT_PATH`. Перед запуском убедиться, что выбрана нужная локальная конфигурация; не печатать содержимое файлов.
- Для новой пустой базы миграции выполняются как отдельный согласованный шаг; для перенесённой сначала сохранить копию и проверить план миграций. Не создавать пустую базу поверх ожидаемой наполненной.
- Подготовить учётную запись через существующие средства Django. Для редактора нужны `is_staff` и `content.view_page`, `content.add_page`, `content.change_page`. Не выдавать суперпользователя только ради обхода ошибки прав.
- Главная страница требует опубликованной домашней Page. Отсутствие начальных данных не исправлять безусловным демонстрационным наполнением.

## Запрос «Запусти сайт»

После первой настройки выполнять из корня проекта:

```powershell
uv run --locked --extra dev manage check
uv run --locked --extra dev manage startserver 127.0.0.1:8000
```

До запуска проверить, не работает ли уже экземпляр этого проекта на выбранном порту. Не завершать посторонний процесс; выбрать свободный локальный порт или использовать подтверждённый существующий экземпляр. Держать сервер в управляемой сессии инструмента терминала; при отдельном фоновом запуске на Windows использовать скрытое окно и сохранять идентификатор процесса и журналы вне Git. Не утверждать, что процесс переживёт закрытие Codex, без проверки конкретного способа запуска.

Проверить HTTP-ответ главной и страницы входа, затем сообщить автору адрес. Не привязывать dev-сервер к `0.0.0.0` и не открывать внешний доступ как часть обычного локального запуска. Если есть ошибка подключения, отсутствующая миграция или библиотека, назвать причину. Не запускать `migrate` автоматически.

Для локальной работы автора используются SQLite и обычный сервер Django, без
контейнеров. `startserver` собирает стили и скрипты перед запуском и прекращает
запуск при ошибке сборки. Для запуска без повторной сборки допустим `runserver`.
После разрешённых изменений CSS/JS следовать `atlas-design-system`.

Остановка: завершить только собственный подтверждённый процесс сервера и, если нужно для копии данных, относящиеся к этому проекту воркеры. Не использовать массовое завершение всех Python-процессов.

## Запрос «Сохрани копию»

Применять `tools/handoff/README.md`. Завершить сохранение в редакторе, остановить сервер, воркеры и другие процессы записи в базу/фотографии. Создать и проверить архив. Затем можно возобновить сайт и передать готовый архив через Syncthing. Без установленного расписания копии создаются только по запросу; не обещать автоматическое ежедневное сохранение.

Архивы хранить вне репозитория и рабочей media-папки. На принимающем компьютере настроить независимую историю версий. Настройки Syncthing и удаление старых архивов выполняются отдельно; наличие файла в исходящей папке не доказывает доставку.

Восстановление сначала выполнять в новую отдельную папку. Проверить архив, базу и фотографии; запуск восстановленного сайта возможен только с явно изолированными путями к восстановленным данным. Подмена рабочих данных — отдельное согласованное действие после новой копии текущего состояния.

## Запрос «Получить изменения разработчика»

Репозиторий — `https://github.com/CodexDLC/TILE.git`. Проверить `origin`, текущую ветку и локальные изменения, получить удалённые сведения и посмотреть состав обновления. Для чистой `develop` допустим `git pull --ff-only origin develop`. При расхождении истории или незакоммиченной работе не делать `reset --hard`, принудительную отправку либо скрытое удаление файлов; сохранить работу и разрешить конфликт в рамках запроса.

Перед обновлением с миграциями остановить запись и сохранить копию. Запрос на обновление кода не отменяет правила согласования схемы в `atlas-working-modes`. При изменении зависимостей использовать согласованные версии и lock-файл, обновить библиотечные навыки официальным механизмом пакета. Проверить сайт после обновления.

## Приёмка нового компьютера

- Проверить путь установки, выбранную локальную базу и media, версии библиотек и загрузку навыков.
- Пройти вход, черновик, фото, предпросмотр, публикацию и снятие на отдельной проверочной базе. Рабочий материал автора менять только по её поручению.
- Перезапустить сайт и проверить сохранность данных.
- Создать архив синтетической или согласованной рабочей базы, проверить передачу через Syncthing и восстановление в отдельную папку.
- Записать фактический результат и оставшиеся ограничения в `docs/handoff/README.md`, не помещая туда пароли и персональные настройки.
