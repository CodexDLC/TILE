# Первая редакция проектных навыков TALE

> Обновление: после разрешения владельца проектные навыки активированы и добавлены два рабочих режима. См. [запись активации](02-activation.md). Ниже сохранено состояние на момент аудита/подготовки предложения.

Статус: подготовлено для просмотра, **не активировано**. Файлы лежат под `proposed/`, действующие AGENTS.md и docs/agent-skills не изменены. Пути в предлагаемых инструкциях относятся к корню проекта после возможной активации, а не к вложенной папке предложения.

## Подтверждённые проблемы

1. Шесть навыков носят имя lily-* и описывают чужие booking/conversations/notifications workflows. В TALE редактор принадлежит features.content, география — features.places. Чужие примеры могут направлять изменения в неправильные модули.
2. AGENTS.md требует читать весь каталог. Новые глобальные правила требуют выбирать только относящиеся к задаче навыки.
3. Дублируются архитектура, feature-slice, ownership и selectors/services. Важные инварианты фактического редактора — copy-on-write, общая публикация Page, неизменный URL — почти не отражены.
4. Public-template и triage ссылаются на отсутствующий lily-static-assets. Реальный entry импортирует tokens.css_2; это нужно явно проверять, а не следовать имени старого файла.
5. Нет ясной границы между публичным редакционным стилем и рабочим кабинетом, библиотекой и потребителем. Новый library-managed codex-django skill уже содержит API-навигацию; её не нужно переписывать в проект.

## Предлагаемая структура

[Новый AGENTS.md](proposed/AGENTS.md) — короткий маршрутизатор. Каталог `docs/agent-skills` сохраняется; .agents-зеркало не создаётся.

| Текущий навык | Действие при активации | Предлагаемый файл |
| --- | --- | --- |
| change-triage | Переписать под TALE; убрать Lily и несуществующие ссылки | [atlas-change-triage](proposed/docs/agent-skills/change-triage/SKILL.md) |
| architecture | Объединить правила владения и слоёв, сверить с кодом | [atlas-architecture](proposed/docs/agent-skills/architecture/SKILL.md) |
| feature-slice, feature-boundary-decision, model-schema-change, selector-service-discipline | После резервной копии перенести существенные правила в architecture; убрать из активного набора, не оставлять конфликтующие автотриггеры | architecture выше |
| page-blocks | Сохранить typed blocks, добавить фактический редактор/языки/публикацию | [atlas-page-blocks](proposed/docs/agent-skills/page-blocks/SKILL.md) |
| cabinet-feature-change | Переписать под автора TALE и библиотечные границы | [atlas-cabinet-feature-change](proposed/docs/agent-skills/cabinet-feature-change/SKILL.md) |
| public-template-change | Переписать под город/историю, языки и маршруты | [atlas-public-template-change](proposed/docs/agent-skills/public-template-change/SKILL.md) |
| design-system | Сохранить public style; добавить source/compile и отдельную роль cabinet tokens | [atlas-design-system](proposed/docs/agent-skills/design-system/SKILL.md) |

Это шесть сфокусированных навыков вместо десяти частично пересекающихся. Точную экономию токенов/подписки не измеряли.

## Проверка предлагаемой настройки

- «Сделай форму статьи понятнее»: cabinet + page-blocks, design-system при CSS; не booking и не все навыки.
- «Исправь меню сайта»: public-template + design-system; модель данных не менять без причины.
- «Поменяй политику переводов»: page-blocks + architecture и тесты; глобальный compatibility decision по реальной задаче.
- «Измени общий sidebar»: library usage-skill cabinet-shell/components и подтверждение канонического источника; проект — только адаптер.
- «Что такое черновик?»: короткий ответ без агентов, полного чтения навыков и изменений.

Это reasoning-проверка маршрутизации, не автоматический eval моделей. У всех шести файлов проверены frontmatter, имена, ссылки и кодовые ориентиры; команды проверялись отдельно с оговорённым временным PYTHONPATH. Обычный uv запуск после переезда не подтверждён.

## Активация отдельным шагом

Перед заменой сохранить recoverable копию текущего AGENTS.md и всего docs/agent-skills. Убедиться, что нет managed-маркеров библиотечного установщика в заменяемых файлах. Заменить только проектные инструкции, обновить ссылки на объединённые навыки, не менять глобальные навыки, библиотечный manifest или runtime. Проверить relative references и триггеры. Пока это только подготовленная редакция.

## Приёмка первой редакции

Один внутренний GPT-6 Sol выполнил независимую read-only проверку предложений с точечным чтением кода. Два замечания внесены: правило наличия текста/фото явно привязано к текущей проверке ArticleForm.clean, а исправление окружения не требует повторного согласования, если оно уже разрешено заданием. Существенных противоречий и неверных путей при этой ограниченной проверке не обнаружено. Это не автоматический eval навыков и не активация инструкций.
