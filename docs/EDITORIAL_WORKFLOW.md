# T.A.L.E. — редакционный процесс

Актуализировано: 2026-10-15 по результатам аудита. Ниже описан требуемый процесс; отличие текущего кода выделено явно.

## Требуемый процесс автора

1. Войти в кабинет с правами редактора, создать историю, выбрать языковую версию RU/DE/EN. Город и его страница проверяются отдельно; не требуется обязательная связь каждой истории с конкретным местом.
2. Добавить заголовок, короткое вступление и именованные разделы с текстом, нужные фотографии и подписи. Возможность добавлять и переставлять раскрывающиеся разделы утверждена 06.11.2026, но ещё не реализована этим решением; см. PR-09 в [требованиях](PRODUCT_REQUIREMENTS.md). Сохранить черновик: неполный материал остаётся закрытым.
3. Открыть авторский предпросмотр с соответствующими правами. Предпросмотр не делает текст, фотографии или аудио доступными участнику пилота.
4. Явно опубликовать текст выбранного языка. Опубликованный текст может существовать без аудио.
5. Подготовить/загрузить запись того же языка, проверить её и отдельно подтвердить публикацию. Загрузка и выбор кандидата на замену не меняют действующую запись.
6. Сохранять правки опубликованного текста и фото в отдельный черновик; читатель продолжает видеть предыдущую редакцию до явной публикации правок. Сохранение и предпросмотр не должны публиковать правки.
7. После изменения текста, с которым проверяли аудио, получить предупреждение о необходимости повторной проверки записи. Само изменение текста не удаляет и не отменяет аудио автоматически.
8. При необходимости снять текст или аудио выбранного языка с публикации. Снятие текста закрывает прослушивание, сохраняя файл и выбор записи. Повторная публикация текста восстанавливает доступ при сохранённой публикации аудио и остальных выполненных условиях.

Действия одного языка не затрагивают остальные. Удаление материала/файла и снятие с публикации — разные действия; политика удаления и сроки хранения ещё не согласованы. Сравнение редакций и интерфейс истории откатов могут быть отложены, безопасное сохранение черновых правок требуется для пилота.

## Таблица пользовательского доступа для одного языка

В [заявке 13 октября](requests/editorial-audio-pilot-proposal.md) также записаны критерии готовности: ошибка публикации не оставляет частично обновлённый материал, устаревшая форма не перезаписывает работу молча, новые запросы заменённой аудиозаписи отклоняются. Это сохранённые критерии заявки; конкретные ограничения моделей, проверка версии формы и механизм выдачи остаются техническими предложениями до согласования разработчиком. Уже полученные браузером данные отозвать невозможно.

| Текст опубликован | Аудио опубликовано | Остальные условия доступа выполнены | Прослушивание |
|---|---|---|---|
| Нет | Любое состояние | Любое состояние | Заблокировано; запись сохраняется |
| Да | Нет | Да | Заблокировано; текст доступен в пределах пилота |
| Да | Да | Нет | Заблокировано |

Авторский предпросмотр использует отдельную проверку прав и не является исключением для обычного пользователя.

## Что есть сейчас по чтению кода 2026-10-14

В [editor.py](../src/atlas/features/content/views/editor.py) и [articles.py](../src/atlas/features/content/services/articles.py) есть создание, редактирование, черновик, предпросмотр, публикация и снятие. Нужны активный staff и соответствующие права `content.view/add/change_page`. Предпросмотр требует входа, имеет запрет кэширования и `X-Robots-Tag: noindex, nofollow, noarchive`.

**Расхождение:** статус `Page.is_published` общий для языков. Сохранение редактирует действующие Page/блоки сразу; отдельного черновика правок опубликованной статьи нет. Кнопка предпросмотра тоже вызывает сохранение. Это не соответствует требуемому безопасному процессу выше.

[ArticleForm](../src/atlas/features/content/forms/articles.py) требует текст и фотографию для публикации (и сохранения уже опубликованного материала); черновик допускает неполный текст, но заголовок обязателен. Аудио не требуется. Это существующее ограничение формы, а не новое согласованное универсальное правило продукта. `save_article` не повторяет эти проверки — другой путь вызова не гарантирует ту же валидацию.

Редактор сохраняет дополнительные блоки, отделяет общие блоки при записи, удерживает существующий город/URL. Рабочего редакционного аудиосценария не найдено. Полный сценарий с реальными правами и воспроизведением в этой задаче не запускался.

Схема редакций и аудиозаписей из [заявки](requests/editorial-audio-pilot-proposal.md) ждёт разработчика. Этот документ не разрешает менять модели, миграции или рабочую базу.

Список статей сейчас показывает общий статус, дату, родительскую страницу и действия редактирования/предпросмотра/открытия; есть фильтр черновиков и опубликованных и пагинация по 20. Отдельных статусов публикации текста и аудио по языкам нет. Проверка `require_author` не ограничивает материал его создателем: активный staff с нужным разрешением работает с доступной статьёй. Это факт реализации, а не согласованная модель разграничения прав между авторами.

Файлы галереи общие для языков, подписи переводятся. Разный состав фотографий по языкам, предусмотренный заявкой, в текущем редакторе не реализован. Защита HTML-предпросмотра не доказывает закрытость самих файлов фотографий.

## Что ещё не определено

Нужны решения о распределении ролей и доступе к чужим статьям, представлении статусов языков/аудио, отмене черновых правок, сообщениях об ошибках публикации, обязательных полях, подтверждении повторной проверки аудио и поведении при отсутствии перевода. Способ предотвращения конфликтов двух вкладок согласует разработчик; интерфейс разрешения конфликта не утверждён. Подробности не восстанавливать по текущим кнопкам или по предложенной схеме моделей.
