# Резервные копии через общую папку libraries

Применять по запросу сохранить базу, сделать дамп или передать резервную копию TALE через Syncthing. Создавать копию по запросу; расписание отдельно не настроено.

## Пути и формат

На настроенном компьютере общая папка `libraries` находится рядом с корнем проекта, внутри workspace. Вычислять пути из фактического корня, а не из пути другой машины:

```powershell
$projectRoot = (Get-Location).Path
$workspaceRoot = Split-Path -Parent $projectRoot
$sharedRoot = Join-Path $workspaceRoot 'libraries'
$archiveDir = Join-Path $sharedRoot 'backups\tale'
$stagingDir = Join-Path $workspaceRoot '.tale-backup-staging'
```

Проверить через локальный Syncthing, что папка `workspace-libraries` действительно указывает на `$sharedRoot`. На другой машине без этой настройки сначала определить согласованный путь. Не создавать новое подключение или делиться архивом с новым устройством автоматически.

База проекта сейчас SQLite. «Дамп» для этого сценария — проверенный ZIP со снимком `database.sqlite3`, фотографиями `media/` и манифестом. Это восстановимая копия базы, а не SQL-текст. Для запроса именно `.sql` или другого backend определить отдельный способ экспорта; не выдавать ZIP за SQL-дамп.

## Создать и передать

1. Прочитать `tools/handoff/README.md` из корня проекта. Проверить фактические `DATABASES["default"]` и `MEDIA_ROOT`, выводя только backend и пути. Не читать и не печатать ключи или содержимое `.env`. Привычные пути `data/db/atlas.sqlite3` и `src/atlas/media` использовать только после проверки.
2. Убедиться, что сохранение в редакторе завершено. Остановить только подтверждённые процессы этого проекта, которые пишут базу или media, включая сервер и воркеры. Если остановка неизвестного процесса нужна, сначала установить его принадлежность. Запомнить, был ли сайт запущен, его адрес и способ запуска.
3. Создать `$archiveDir` и `$stagingDir`, если их нет. Staging должен быть вне синхронизации, на той же файловой системе, что и выходной каталог. Файл архива именовать `tale-<имя-компьютера>-<UTC-время>-<случайный-суффикс>.zip`, чтобы обе машины не перезаписывали копии друг друга. Не удалять старые архивы без отдельного запроса.
4. Из корня проекта выполнить установленным Python проекта:

```powershell
# $databasePath и $mediaPath — проверенные фактические пути.
# $archivePath — новый уникальный файл внутри $archiveDir.
& .venv\Scripts\python.exe -B -m tools.handoff create --database $databasePath --media $mediaPath --staging $stagingDir --output $archivePath --writers-stopped
& .venv\Scripts\python.exe -B -m tools.handoff verify $archivePath
```

Проверять код возврата каждой команды. Утилита проверяет целостность SQLite и хеши, затем атомарно публикует только завершённый ZIP. Не копировать живую SQLite-базу, WAL или незавершённый архив в `libraries`. Архив не содержит `.env`; ключи для восстановления зашифрованных полей владелец передаёт отдельно.

5. Возобновить ранее запущенный сайт даже после ошибки копирования, если это безопасно; проверить HTTP. Не запускать ранее остановленные сервисы, которые до операции не работали.
6. Проверить состояние папки и соединение с согласованным устройством в Syncthing. API-ключ получать из локальной конфигурации только для заголовка запроса, не выводить. Состояние локальной папки `idle` означает готовность локального сканирования, но не доказывает доставку. Сообщать отдельно: архив создан и проверен; устройство подключено или нет; получение подтверждено или не проверено. На принимающей стороне проверить архив штатной командой `verify`.

## Восстановление

Использовать штатный `tools.handoff restore` только в новый отсутствующий каталог; проверить полученную базу и media. Подменять текущие рабочие данные только по отдельному запросу с резервной копией текущего состояния. Не выполнять автоматическое восстановление при появлении архива в Syncthing.
