# Статьи и блоки TALE

Источник маршрута, типа, SEO и публикации — `Page`; порядок секций — `PageBlockSlot`; содержимое — конкретные типизированные блоки через GenericForeignKey. Не заменять typed fields JSON-полем или независимой второй моделью статей без отдельного решения.

Текущий редактор обслуживает STORY и существующие PLACE, основной RichTextBlock, обложку и дополнительные фото. Другие блоки сохраняются и продолжают выводиться: простой редактор не является универсальным конструктором. Общий между страницами блок при записи отделяется copy-on-write, включая изображения общей галереи.

Текущее поведение, подтверждаемое `features/content/services/articles.py`, `forms/articles.py` и tests/content/test_editor.py:

- Ручное создание не требует внешнего ИИ или очереди.
- В авторском редакторе ArticleForm.clean требует текст и фотографию для публикации; черновик допускает незавершённость. Аудио не требуется. Сам save_article эти условия повторно не проверяет: при добавлении другого пути вызова обеспечить ту же валидацию на уровне сервиса и проверить её тестом. Не считать текущую проверку формы гарантией для всех вызовов сервиса.
- Права: active staff и соответствующие content view/add/change_page; проверять сервис и endpoint, не только меню.
- Предпросмотр требует доступа, no-store/noindex; черновики исключаются из публичных выборок и sitemap.
- Существующий URL и привязка к городу сохраняются при редактировании.
- Обновление опубликованной статьи применяется сразу. Отдельных версий правок/согласования пока нет.

Языки RU/DE/EN. Язык интерфейса и язык содержимого различаются. Использовать raw-поля выбранной версии для заголовка/вступления/SEO; не выдавать fallback другого языка за перевод. Выбор article_language учитывает title и основной текст. Общий статус публикации принадлежит Page, а не каждой версии. Критерии sitemap сейчас требуют отдельного согласования с полнотой текста — не называть это уже решённым.

Проверки по затронутому контракту: draft→preview→publish→edit→unpublish; реальные права; неполный перевод; стабильный URL; сохранность дополнительных/общих блоков; изображения; публичный поиск и sitemap. Только изолированная тестовая база/медиа.
