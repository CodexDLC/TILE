# Визуальная система и сборка

Публичный TALE: тёплые нейтральные фоны, бронза, спокойные зелёные тёмные области, Fraunces/Inter/Playfair Display Italic. Подробности: `docs/design/README.md`; статические preview/ui-kit — образцы, не готовый продукт и не разрешение включать все их функции.

Кабинет: приоритет задачи, состояния, действия и восстановления. Не переносить большие public hero в рабочие формы. Использовать `--cab-*` и проектные overrides; бренд TALE не вносить в общую библиотеку.

Перед CSS-правкой проследить фактический source→compiler→loaded stylesheet:

- Публичный entry — `src/atlas/static/css/base.css`, конфигурация — соседний compiler_config.json, результат app.css.
- В текущем entry импортируется `base/tokens.css_2`; не считать tokens.css_1 каноном по имени и не удалять альтернативы без отдельного решения.
- Оболочка библиотеки подключает собственные styles и optional project `cabinet/css/app_cabinet.css`.
- Проверить реально загружаемый JS. Текущая public compiler-config содержит совпадающий JS source/output; не менять сборку вслепую.

Редактировать исходники, не минифицированный результат. Сборка после разрешённых asset-изменений: `uv run --locked --extra dev manage compile_assets` только в исправном окружении; проверить пути и получившийся вывод. Не запускать сборку как побочный эффект аудита.

Одна совместная UI-приёмка по глобальным ui-ux/server-template-dashboard/frontend-design правилам, без дублирования нескольких обязательных циклов: реальные desktop/mobile снимки, основные взаимодействия, язык, клавиатура, ошибки/пустые состояния. Сохранить доказательства и назвать непроверенное. Контрастный риск не выдавать за WCAG-сертификацию по фотографии экрана.
