# Atlas

Авторский атлас-путеводитель на Django. Здесь описан локальный запуск на Windows.

## Окружение

Используется Python 3.14 (ветка закреплена в `.python-version` и `pyproject.toml`).
Команды выполняйте через `uv`: системный Python может содержать другие версии библиотек.

Из корня проекта:

```powershell
# Выполнять в терминале, открытом в фактическом корне проекта.
uv sync --locked --extra dev
uv run --locked --extra dev manage check
uv run --locked --extra dev manage runserver
```

Откройте http://127.0.0.1:8000/ . Остановка сервера — Ctrl+C.
Команда `manage` также работает из `src\atlas`: повторно добавлять `src\atlas` к пути не нужно.
Если запускаете непосредственно файл из этой вложенной папки, используйте
`uv run --locked --extra dev python manage.py runserver`.

При первом запуске с новой базой выполните `uv run --locked --extra dev manage migrate`.
Это изменяет схему базы; для существующей базы сначала сделайте резервную копию.
Публичная главная страница требует опубликованной домашней страницы в базе.

## Зависимости из PyPI

Встроенное AI-создание и автоматический перевод страниц отключены. Материалы и
языковые версии можно подготовить через чат и сохранить вручную. Для обычной
авторской работы не нужны переводчик-worker, AI-ключи или Redis.

Все зависимости устанавливаются из реестра PyPI по `uv.lock`; соседняя папка
`codex_tools` и локальные исходники библиотек для запуска не требуются.
Для перехода закреплены опубликованные версии: `codex-ai==0.2.6`,
`codex-core==0.5.0`, `codex-django==0.7.0`, `codex-django-cli==0.4.0`,
`codex-platform==0.6.0`, `codex-services==0.1.4`.
Обычная установка: `uv sync --locked --extra dev`. Не обновляйте lock-файл ради запуска;
`uv lock` нужен только при намеренном согласованном изменении зависимостей.

Если `uv` сообщает об ошибке доступа к кэшу, который указывает на старую папку
другого расположения проекта, задайте доступный кэш для текущей сессии и повторите установку:

```powershell
$env:UV_CACHE_DIR = Join-Path (Get-Location) '.uv-cache'
uv sync --locked --extra dev
```

## Библиотечные навыки

Навыки всех шести библиотек установлены штатными установщиками в `.agents/skills/codex-*`;
ссылки на них добавлены в `AGENTS.md`. Эти файлы и манифесты переносятся через Git.
После изменения версии библиотеки обновите её управляемый навык и проверьте статус:

```powershell
uv run --locked --extra dev python -m codex_django.agent_skills update --project .
uv run --locked --extra dev python -m codex_django.agent_skills status --project .
```

Аналогичные команды доступны для `codex_ai`, `codex_core`, `codex_django_cli`,
`codex_platform` и `codex_services`. Управляемые файлы не редактируйте вручную.

## Настройки и IDE

Локальные настройки берутся из `.env`; перечень параметров приведён в `.env.example`.
Не публикуйте `.env` с паролями и ключами.

В PyCharm выберите интерпретатор `<корень проекта>\.venv\Scripts\python.exe`.
Для обычной Python-конфигурации запуска задайте:

- script: `<корень проекта>\src\atlas\manage.py`;
- parameters: `runserver`;
- working directory: корень проекта.

Сервер разработки использует настройки `atlas.core.settings.dev`.
Почта, фоновые очереди и ИИ требуют отдельной настройки; обычный запуск сервера не проверяет их доставку.

## Проверки

```powershell
uv run --locked --extra dev python -m pytest -q
uv run --locked --extra dev ruff check src tests
uv pip check --python .venv/Scripts/python.exe
```

Тесты используют SQLite в памяти, локальный кэш и почту в памяти.
В тестовых настройках отключены рабочие Redis/ARQ-подключения и файловые логи.
`django_debug_mode = true` сохраняет штатное отключение Redis в библиотеках при локальных тестах;
проверки поведения production должны явно переопределять настройки и подменять внешние сервисы.

`runserver` не пересобирает стили и скрипты. После их изменения используйте
`uv run --locked --extra dev manage compile_assets` или команду `manage startserver`,
которая выполняет сборку перед запуском. Сборка обновляет генерируемые файлы.

## Передача автору: новый компьютер

Пометка от 2026-10-10. Первую настройку выполняет разработчик. Установка зависимостей из PyPI и тесты после перехода проверены в текущем окружении разработчика; установка и авторский сценарий на новом компьютере ещё не проверены. Пункты ниже ещё нужно выполнить на новом компьютере.

- [ ] Открыть проект в ветке `develop`: это рабочая ветка автора. Не переносить старую `.venv`; создать окружение заново.
- [ ] Установить зависимости из PyPI командой `uv sync --locked --extra dev` с текущим `uv.lock` и проверить окружение. Локальные исходники `codex_tools` не требуются.
- [ ] Установить глобальные навыки по [инструкции переноса](tools/skills-transfer/2026-10-09/README.md). Проектные `AGENTS.md` и `.agents/skills/` уже находятся в репозитории. Проверить доступность навыков в новой сессии агента.
- [ ] Проверить штатной командой `status` навыки всех шести библиотек, перенесённые с репозиторием, и их обнаружение в новой сессии агента.
- [ ] Поднять локальный сервер сайта на новом компьютере: подготовить локальные настройки, SQLite-базу, фотографии и учётную запись автора; проверить вход, сохранение статьи, загрузку фотографии и повторный запуск. База и фотографии переносятся отдельно от Git. На первом этапе использовать SQLite без Docker.
- [ ] Установить и настроить Syncthing на новом компьютере, подключить его к компьютеру разработчика и настроить общую папку для готовых резервных копий. Рабочую SQLite-базу напрямую не синхронизировать.
- [ ] Настроить создание согласованных резервных копий базы и фотографий: сначала завершать архив вне синхронизируемой папки, затем помещать готовый архив в неё. Хранить несколько версий, включая независимую историю на принимающем компьютере; проверить передачу и восстановление. Расписание и автоматизация пока не настроены.

Первое сообщение агенту: «Я работаю как автор TALE; объясняй просто и конкретно».

Переключение Git-ветки не переключает базу данных. Перед изменениями схемы сохранять резервную копию рабочих данных и соблюдать проектные правила согласования.

Инструкции выполняет агент, а не автор: [локальные операции](docs/handoff/agent-operations.md). [Состояние передачи и оставшиеся шаги](docs/handoff/README.md).
